RQ1 Execution Flow — Planner-Executor vs Single-Agent ReAct

Three phases: ① SLURM job & vLLM bring-up, ② generation via run_rq1.py, ③ offline scoring + paired-bootstrap stats. Generation runs locally on Qwen via vLLM; scoring uses hosted gpt-4o-mini to parse NL plans and the upstream constraint checkers.

Scroll to pan · diagram renders client-side via Mermaid (needs internet for the CDN).

Notes. Phases ② and ③ are decoupled: run_rq1.py only generates NL plans on the cluster (vLLM/Qwen, no scoring); scoring runs later. The executor is identical across both configs — only the injected plan differs (the “matched compute” lever). Two fallbacks guarantee a per-query answer: planner JSON failure → degraded plain-ReAct, and resumability re-runs only missing idx.
